# One-pass finding reuse — November 6, 2026

**Decision: prefer the ordinary cached-note baseline for this measured workload.**
Neither repeated pair nor the primary workflow allocation meets the declared
savings rule. The independently accepted source adds
per-dependency `read_guidance` to `inspect --id FINDING --brief`, alongside the
existing note, metadata and full integrity/freshness checks. Changed readable
evidence calls for a current read; unavailable, corrupt, stale or mismatched
evidence calls for validation/recovery. Matching current bytes never approve
interpretation, scope, assumptions or external premises automatically.

## Comparison boundary

Both arms receive the same cached personal-site pages, ordinary note, provenance,
freshness policy and equivalent validation opportunities. One neutral native
session authored the note; its exact unedited bytes were shared with four fresh
return sessions. Pair 1 ran baseline then treatment; pair 2 ran treatment then
baseline. Each return handles unchanged, relevant synthetic change, contextual
change and missing/stale cases. Every actual note dependency remains intact.

These are historical first-party page captures with loopback HTTP validation and
synthetic controls, not fresh public-site validation or a new live work occasion.
Original dates, max_age=3600, full audits and HTTP metadata including max-age=0
remain unchanged. Independent cost-blind review grades complete answers and
command evidence before costs; command syntax can reveal an arm, so full arm
blinding is not claimed. The previous [native comparison](native-tokens-20261106.md)
remains unchanged and used a different initial-note design.

The selected model/effort is GPT-6.1 Sol / High through existing Codex login.
An external default-model change interrupted three unstarted sessions across the
study. The exact other configuration bytes were proven unchanged. A prospective
amendment pins the original model/effort for those sessions without changing user
settings, replacing completed runs, adding cases or expanding the ten-session
cap. The interruption and all original approvals remain. Native events do not
independently report backend model identity; selected settings and launch hashes
are the available evidence.

## Accounting and decision

All 34 answers across both products passed independent cost-blind grading:
202 applicable dimensions passed, two symmetric initial-change dimensions were
not applicable, and none were partial or failed. All ten planned native sessions
completed with unchanged inputs; there were no native retries or timeouts.
In-session command failures and warnings remain in the recorded usage.

Native `turn.completed.usage` supplies input, cached input and output. Cached input
is a subset of input. **U = input − cached input + output** and **T = input + output**.
The primary alternative workflow allocation is the shared initial plus that arm's
two returns. Equal initial attribution to each alternative is not two executed
initial sessions. Actual study totals count each real session once.

PageDigest's primary U rises 51.22% and T rises 0.34%. The product has
48,000 fewer provider-cached input tokens across the two returns. That cache
difference accounts arithmetically for most of the U increase, but does not prove
that the interface caused it. The return-only aggregate and both individual pairs
also miss the joint rule.

The actual two-product study used **447,569 U / 1,855,697 T**, counting each
shared initial once and every return once. Seven sessions ran before the config
interruption and three resumed under the reviewed amendment. These actual totals
must not be calculated by adding the alternative workflow allocations.

The predeclared rule requires complete quality/freshness, at least 10% lower
primary U and no higher primary T. Every pair and the return-only aggregate remain
visible; two pairs cannot establish robust, causal or universal savings. Provider
cache and reader strategy vary despite identical local source caches.

## Observed commands and bytes

Across both returns, baseline/product used 10/11 recorded shell commands and
108,732/119,998 explicitly metered source-body bytes. Both did 24 exposed integrity
reads totaling 442,578 bytes. In pair 2, the product reread both unchanged required pages; baseline instead
read the missing/stale project body as historical material, leaving one net extra
product body read. Every reader separately requested metadata. First recall output
was 30,706 bytes for baseline and 37,855 for product. Total exposed command-output
bytes were 105,624/125,056. The additional guidance was not a smaller response than
the competent baseline. These observed command/body/output layers do not prove
why token usage or provider caching differed and must not be added together.

No new remote acquisition occurs. Local validation and source-read bytes are
separate layers, not an invented combined total. Original acquisition, publisher
upkeep, human attention, implementation/coordinator/reviewer tokens and monetary
or all-in costs remain unknown. Manifest overhead in the actual full-audit pilot
is a separate observed cost; this comparison isolates reader guidance above an
equally equipped cache and note.
